# §15 — Final Engineering Principles

> **Source:** Django Backend Engineering Standards  
> **Back to index:** [00_index.md](./00_index.md)

Use these principles as **decision-making guidance**, not as a checklist to apply mechanically.

---

## 15.1 Principles

| # | Principle |
|---|---|
| 1 | Correctness before optimization. |
| 2 | Security and data integrity from the beginning. |
| 3 | Simple solutions before complex architecture. |
| 4 | Explicit business rules over hidden behavior. |
| 5 | Database constraints as a final integrity boundary. |
| 6 | Small, reviewable changes over large rewrites. |
| 7 | Automated tests throughout development. |
| 8 | Measure performance before optimizing. |
| 9 | Fail safely and log enough to investigate. |
| 10 | Document important decisions and trade-offs. |
| 11 | Preserve existing behavior unless a change is intentional. |
| 12 | Build for current requirements while leaving room for reasonable growth. |

---

> **The standard to aim for:** Django code that is understandable, secure, testable, efficient, reliable, and straightforward for another developer or AI agent to maintain.
